# Exact kernel, stage 3: the controller's rulings

These are the decisions taken on the owner's behalf while stage 3 was built. They are copied verbatim from the SDD ledger, in the order they were made, each with its cost if wrong. The plan is `docs/superpowers/plans/2026-11-25-exact-kernel-stage3-construction.md`. The owner approved it on 2026-11-26 with amendments A1–A5, listed below.

Stage 3 shipped in two PRs: #246 (Tasks 1–5 and 13–15, merged as 25b1947b) and #247 (the rest).

## Owner amendments

- Amendment A1 (→ Task 10): on an exact part, a selected/hovered face's highlight overlay is drawn from the BRIDGE copy's facets of that logical face (so a coarse 6/8-segment part shows the chords the user actually clicks), not from the exact display mesh.
- Amendment A2 (→ Tasks 11/12 wording + test): a lost reference never stops a part being written: it marks the part read-in-part, so Save becomes Save As and replacing the original asks first with Cancel the default (the existing rule); add a test that a migrated part with a lost reference can be saved as a new file and saved over its original after explicit confirmation. The plan's "which does block it" wording is wrong → "which forces Save As or an explicit confirmation".
- Amendment A3: the 0.35 rad display floor is superseded by #245 (0.5 rad + part-relative tolerance, merged 6e822892) — update the plan's "Kept from stage 2" line.
- Amendment A4 (→ Task 15, sent to the running implementer as Ruling 14): measure where and how much the validator's O(n²) checks cost in Release on open/rebuild of the largest imported bodies; if >10% of open time or >100 ms on any, add a verdict-preserving prefilter (bbox sweep / math::RTree).
- Amendment A5 (→ Global Constraints): commits stay separated by concern — exact builders, bridge wiring, consumers, migration — one task's work per commit series, never mixed, so a corpus regression bisects cleanly.

## Rulings

- Ruling 1: Run Tasks 1, 3, 13, 14, 15 before the owner's review; hold 2, 4–12 — they are needed whatever the owner decides on the plan's flagged decisions (two solids, drawings via the bridge, one PR), and the branch is unmerged — cost if wrong: the owner redirects the kernel work itself (unlikely; the spec mandates it), and those commits are reverted on the branch.
- Ruling 2: A torus primitive with R <= r (horn or spindle) is the "apple": the revolution of the part of its tube circle outside the axis, as a NURBS surface of revolution, with poles where the circle meets the axis; its closed-form volume is Pappus over that circular segment. If master's PrimitiveFeature refuses R <= r, the feature keeps refusing (the builder still serves revolve) — cost if wrong: a later stage wants the lemon too; it is a second face, added then.
- Ruling 3: Task 15's timing is measured with Task 13's peak search in place, and Task 15 keeps Task 13's shared measuring function intact — the stage 2 lesson: growth and validation share one measure — cost if wrong: Task 15's targets are harder to meet; any overshoot is a ruling with its numbers.
- Ruling 4: `Pattern::transformed`'s old overload ignores the new `problem` (master's behaviour: a non-similar copy loses its exact fields); no production caller transforms non-similarly — cost if wrong: a future caller loses exactness silently; it must use the `problem` overload (noted in the header comment).
- Ruling 5: A sheared sphere's copy drops its exact fields with the reason in `problem` (pcurveOn cannot fit the pole-to-pole seam on its NURBS form) — reported, not silent; no production caller shears — cost if wrong: a later stage that shears spheres needs a pole-aware NURBS pcurve.
- Ruling 6: Pcurves on faces already NURBS are kept, not refit, under a non-similar transform — an affine map commutes with NURBS evaluation, so (u, v) stays on the moved surface; only converted typed faces are refit — cost if wrong: none expected; the validator runs on the copy in the tests.
- Ruling 7: The numeric constants in Task 1 (determinant floor 1e-12 relative, 5%/10% box margins, 1e-9 whole-period test, 1e-12 period snap) stand — they are floating-point guards on parameter arithmetic, not geometric tolerances, so the "tolerances from ModelTolerance" constraint does not govern them — cost if wrong: a guard trips on a legitimate extreme input; it fails with a reason, never silently.
- Ruling 8 (plan-mandated finding, Task 1 minor 10): Lines and planes stay typed under a non-similar transform — an affine image of a line is a line and of a plane is a plane, and converting them makes a sheared block export B-spline faces and blinds plane/line recognition; the plan's "convert each typed surface and curve" was over-broad. Not blocking (no production caller transforms non-similarly): deferred to the final review's fix wave with the minors above — cost if wrong: none; it only keeps types.
- Ruling 9: A cusp pole (a pole where the surface's meridian meets the axis tangentially or so steeply that the read point would refine below the model's resolution) is refused by the read point AT ONCE (under 0.5 s in Debug) with a reason naming the cusp, decided up front from the pole's geometry rather than discovered by refining; horn tori and near-horn spindles go on stage 3's regression list ("Regression list (in progress)" under the spec's stage 3 entry, committed now, which Task 16 completes); cusp-pole meshing (grading) is carried to a later stage. The builder keeps building them (validation and mass are exact) — cost if wrong: a horn torus cannot be displayed until the later stage; it says so at once instead of stalling.
